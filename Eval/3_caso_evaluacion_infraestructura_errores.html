Consigna general

La empresa TecnInutil SRL fue contratada para diseñar e implementar una infraestructura de servidores Linux virtualizada para su cliente Comercial del Sur, una empresa mediana con una red local de 30 equipos.

La infraestructura debía incluir tres servidores corriendo en VirtualBox sobre un equipo con Windows 11 como sistema anfitrión:

ServidorFunciónSoftware principal
SRV-BDBase de datos relacionalMySQL Server
SRV-WEBServidor webApache HTTP Server
SRV-SMBServidor de archivos compartidosSamba

TecnInutil SRL entregó a su cliente un documento de planificación y un registro de implementación. Sin embargo, el proyecto presentó múltiples fallas desde el principio.

Tu tarea es analizar la documentación producida por TecnInutil SRL e identificar los errores cometidos, explicando en cada caso qué está mal, por qué es un problema y cómo debería corregirse.

A.3. Procedimiento de creación de las VMs

  1. Crear SRV-BD desde cero usando la ISO de Ubuntu Desktop 22.04 LTS.
  2. Crear SRV-WEB desde cero usando la ISO de Ubuntu 23.10.
  3. Para crear SRV-SMB, copiar el archivo .vdi del disco de SRV-WEB usando el Explorador de archivos de Windows. Luego crear una nueva VM en VirtualBox y asignarle ese archivo copiado como disco duro.

A.4. Política de acceso y seguridad

  • En todos los servidores se creará el usuario admintech con contraseña 123456.
  • Se habilitará SSH en los tres servidores.
  • La contraseña del usuario root de MySQL también será 123456, igual a la del sistema, para mayor facilidad.
  • El acceso a MySQL desde aplicaciones de red se realizará con el usuario root directamente.

A.5. Plan de puesta en producción

Una vez que los tres servidores estén configurados y los servicios instalados, se procederá a notificar al cliente para comenzar a utilizarlos. No se contempla ninguna etapa de prueba o punto de restauración previo. No se establece ningún plan de respaldo (backup) de los datos almacenados en los servidores ni de los archivos de configuración.

Parte B — Registro de implementación de TecnInutil SRL

El siguiente registro documenta los comandos ejecutados y archivos de configuración creados durante la implementación. Contiene 9 errores en la ejecución. Identificalos, explicalos y proponé la corrección adecuada.

B.1. Configuración de red — SRV-BD

El técnico configuró la IP estática de SRV-BD editando el archivo de Netplan. El archivo /etc/netplan/00-installer-config.yaml quedó de la siguiente manera:

network:
	version: 2
	renderer: networkd
	ethernets:
		enp0s3:
			dhcp4: no
			addresses:
				- 192.168.1.10/24
			routes:
				- to: default
				  via: 192.168.1.1
			nameservers:
				addresses:
					- 1.1.1.1
					- 8.8.8.8

Luego el técnico ejecutó:

sudo netplan apply

B.2. Instalación y configuración de MySQL — SRV-BD

El técnico ejecutó los siguientes comandos:

sudo apt update
sudo apt download
sudo apt install -y mysql-server
sudo systemctl start mysql
sudo systemctl enable mysql

Luego verificó que el servicio corriera con sudo systemctl status mysql. Al ver que estaba activo, consideró la instalación completa. No se ejecutó mysql_secure_installation ni se modificó ningún archivo de configuración de MySQL.

El archivo /etc/mysql/mysql.conf.d/mysqld.cnf quedó con sus valores predeterminados, incluyendo la siguiente línea sin modificar:

bind-address            = 127.0.0.1

B.3. Configuración de red — SRV-WEB

El archivo /etc/netplan/00-installer-config.yaml del servidor web quedó configurado de la siguiente manera:

network:
  version: 2
  renderer: networkd
  ethernets:
    enp0s3:
      dhcp4: no
      addresses:
        - 192.168.1.20/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses:
          - 1.1.1.1
          - 8.8.8.8

B.4. Instalación y configuración de Apache — SRV-WEB

El técnico ejecutó:

apt update
sudo apt install -y apache2
sudo systemctl start apache2
sudo systemctl enable apache2

Probó desde el mismo servidor con curl http://localhost y vio la página de bienvenida de Apache. Consideró la instalación exitosa y pasó al siguiente servidor.

B.5. Configuración de red — SRV-SMB

El archivo /etc/netplan/00-installer-config.yaml del servidor SMB quedó de la siguiente manera:

network:
  version: 2
  renderer: networkd
  ethernets:
    enp0s3:
      dhcp4: true
      addresses:
        - 192.168.1.30/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses:
          - 1.1.1.1
          - 8.8.8.8

B.6. Instalación y configuración de Samba — SRV-SMB

El técnico ejecutó:

sudo apt update
sudo apt install -y samba
sudo mkdir /srv/compartido
sudo chmod 700 /srv/compartido
sudo chown root:root /srv/compartido

Luego editó /etc/samba/smb.conf y agregó al final:

[global]
   workgroup = WORKGROUP
   server string = Servidor de Archivos TecnInutil

[compartido]
   path = /srv/compartido
   browseable = yes
   read only = no
   guest ok = yes

Por último verificó con sudo systemctl status smbd. Al ver que estaba activo, dio la tarea por finalizada.
